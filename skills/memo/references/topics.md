# Topics And Retrieval

INDEX has a short hand-written header and a generated catalog. The header holds purpose and only recurring project-specific working agreements, in the project's own vocabulary. Read INDEX, then the topic README, then the note that README links. The catalog lists each `topics/<domain>/README.md` as `[title](relative path): description`. It does not list sub-notes. A `## tasks` group then lists at most 5 tasks (`ProjectIndex.TASKS_IN_INDEX`), one line with status: `[title](relative path): description (status)`. Those 5 are the most recently updated, newest first. Status does not change the order. Local mode uses the knowledge file's mtime. GitHub mode uses the committer time of the last commit that touched the file. A task changed in the current save counts as updated then. No `updated` field is stored. Equal times break by path. When more tasks exist, the group ends with `更多任务 N 个，见 [tasks/INDEX.md](tasks/INDEX.md)`. `tasks/INDEX.md` lists every task in that same order, is regenerated on every save that touches the scope, and is not injected. `spec_edit` rewrites the block between `<!-- gei:index start -->` and `<!-- gei:index end -->` for each scope the batch touches, in the same save as a create, edit, rename, or delete. Text outside a matched pair is kept. A start marker with no end marker after it is the generated block through the end of the file; text before that start is kept, and an end marker that appears only before the start does not close the block. Titles and descriptions are rewritten so every `<!--` is neutralized and every backslash is escaped. The heading is the first ATX H1 outside fenced code and HTML comments. Descriptions drop `[` and `]`. U+0085, U+2028, and U+2029 fold into spaces. Edit a document's title, `description`, `type`, path, or task `status` to change its line. `context/INDEX.md` lists topic READMEs the same way when `context/topics/<domain>/README.md` exists. When context has no topic README, it lists `context/notes/` grouped by `type` instead, and still adds the task group. The user need not maintain AGENTS.md. Existing user or repository instructions still govern. Do not copy generic host instructions here.

Keep the hand-written header small. The project and shared Hooks cap the comment-stripped index bodies at 3 KiB (project) and 1 KiB (shared). Whole-output limits are 4 KiB and 1.5 KiB, including paths. Maintenance targets remain below 2 KiB and 768 bytes. These are UTF-8 byte budgets, not measured token counts. Injection keeps complete lines and names the clipped source. The stored INDEX lists topic READMEs and the task window, not every note. `tasks/INDEX.md` lists every task. Merge or delete documents to shorten a clipped catalog. Do not hand-prune generated lines. Keep the header and each catalog line on short complete lines.

A topic page should answer which business terms belong here, what this domain owns, which non-obvious constraints could change the solution, where the code and native-doc entry points are, and which note routes matter. Reuse native documentation by linking to it. External summaries earn space only when they resolve actual ambiguity or expensive repeated exploration.

## Read Path

1. Match the request's business terms or tradeoff dimensions to the INDEX routes already in context. Follow their links without a preliminary INDEX tool read. If the index is missing (including after compaction), clipped, needs refreshing, or the hand-written header must be edited, retrieve it through `spec_read`.
2. Read the matching topic README. Open a note only from a link in that README, then only relevant source, tests, or native docs.
3. Search within the topic using terms, symptoms, alternatives, and selection criteria when no direct route matches. Listing previews are not verified summaries. See [tools](tools.md). Continue a listing only when the requested scope needs it, rather than reading the full notes corpus.
4. Expand only for a concrete dependency or missing owner. Use repository search when knowledge is absent.
5. Stop when scope, constraints, important unknowns, and verification are clear.

A long topic should shed redundant and retired content before splitting. Split by responsibility only when lookup gets difficult and the remaining responsibilities benefit from selective reading. Do not prebuild taxonomy, a central chronological list, generated per-module skills, embeddings, or a knowledge graph. INDEX and `tasks/INDEX.md` are the generated lists. Neither copies a note body.

## Write Path

A topic README uses `type: facts` and a one-line description. Whoever edits the README writes that description by hand to summarize the notes it routes to; INDEX copies it and does not aggregate notes. The [facts example](../templates/facts.md) is the shape, including its short Routes block. Other field rules are in [Memo Shape](../SKILL.md). Note types and handoffs: [notes](notes.md). A task worth resuming is a `tasks` document. A done task stays in `tasks/INDEX.md` and in search. Link each topic note from its README; `spec_check` reports `orphan_note` when that link is missing. Cross-domain references link to the owner. Do not add a second hand-written route list in INDEX. Environment observations and unfinished operations stay in scoped records and are removed when they no longer apply.

Correct known stale claims in the same task. Merge overlapping notes. Remove content made redundant by a reliable code, test, or native-doc authority. Retain superseded rationale only while it can change future judgment. A different branch does not by itself retire an applicable constraint.

Avoid repeating detailed facts between a topic and its notes. Markdown folding does not reduce raw-file input. Separate detail into linked files when selective reads need it.
