# Task References

Use `docs/` only when an accepted task must survive a session boundary or be handed to another agent/person with more fidelity than the current conversation provides.

Start from `templates/task-reference.md` and preserve its fixed sections: Goal, Accepted Decisions, Constraints, Recovery Route, Open Questions, and Verification. Prefer links to code, schemas, artifacts, issues, or sources over copied content.

Do not create a task document for routine work, as a mandatory planning phase, or as a second changelog. Update or remove stale task documents when their recovery value ends.
