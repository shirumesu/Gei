# Overview

Use this reference when Project or Group purpose, responsibilities, boundaries, shared language, or context routes changed.

Preserve the template's fixed sections. Write the minimum background a capable agent cannot recover cheaply from the current task alone:

- **Purpose / Shared Purpose**: why this scope exists.
- **Responsibilities**: outcomes owned here, not an inventory of code.
- **Boundaries And Relations / Project Boundaries**: what belongs elsewhere and which scopes interact.
- **Context Routes**: which `IMPACTS.md`, memory index, Group, Project, or task reference to read next.
- **Authority** when present: evidence beats the Spec.

For a Project, route structural questions to `ARCHITECTURE.md` and recent-change questions to `CHANGELOG.md`. Keep those details out of the injected Overview itself.

Do not copy framework versions, dependency lists, routine commands, directory trees, module descriptions, or facts obvious from a focused code read. Put a non-obvious recurring exception in Memory; put a missed downstream consequence in IMPACTS.

An Overview should remain small enough to inject at SessionStart. When details grow, route them to the owning Project Architecture, Project/Group IMPACTS, Changelog, memory entry, or task document instead of expanding the Overview.
