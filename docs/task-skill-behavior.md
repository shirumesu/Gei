# Task Skill Behavior Checks

Small isolated comparisons inform the scope of these Skills. They do not establish a general quality improvement or reliable trigger rates.

Separate agents received the same fixtures and requests, with either the previous Skills or the revised candidate. A third agent completed the Work fixture without a Skill. Agents had no surrounding design discussion or expected answer. Reports and generated fixtures stayed in ignored scratch storage; only Work fixtures could be edited. Each condition ran once, without randomized order or blind scoring.

| Task and fixture | Previous Skill | Revised candidate |
| --- | --- | --- |
| Review an offline task view. The brief requires undated unfinished tasks, opt-in completed tasks, and consistency with a neighboring calendar. The renderer filters out undated tasks and omits a completed toggle and empty state; its action label/style differs. | Found all four issues and disclosed that rendered appearance was unverified. | Found the same issues, separated the style improvement from functional defects, and disclosed the same visual limit. No demonstrated detection gain. |
| Design a two-week improvement for a 180-page documentation site with three editors. The proposal is vector search plus chat; evidence identifies vocabulary mismatch and scattered answers, while some questions require cross-page explanations. | Recommended synonyms and answer pages, compared alternatives, and proposed falsification checks. | Made the competing cited-answer flow and ownership more concrete; challenged the preferred design with a cross-page task counterexample and refined the validation target. This is an observed qualitative difference, not a general design score. |
| Add a CSV export CLI flag to include archived tasks; default exports must exclude them. A helper test already passes while the CLI exports everything. Preserve the callable API and CSV shape. | Implemented the option through the CLI and helper; actual CLI and API checks passed. | Implemented the same behavior and verified both surfaces. The no-Skill run also passed; this fixture showed no completion advantage from Work. |

The Work candidate initially included a longer verification table. After the comparison it was reduced to delivery-path tracing, causal diagnosis, consumer-level evidence, and conditional references. This final condensation received structural checks, not another independent behavior run. Work is retained as a compact integration convention; improved coding ability is not claimed.

The design scenario was a single-turn proposal. Multi-turn convergence, genuinely novel alternatives, large-project changes, live visual review, and explicit security-audit coverage remain unmeasured. No report claimed browser rendering from source inspection. Further evaluation should use actual recurring misses rather than repeating these easy fixtures.

## Design References

- [Matt Pocock's grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md) organizes questions by decision dependencies and distinguishes discoverable facts from user decisions. Consider adopts dependency-aware questioning while retaining responsibility for proposing designs and choosing routine details. It does not require exhausting every decision or requesting fresh approval for already authorized work.
- [Superpowers brainstorming](https://github.com/obra/superpowers/blob/main/skills/brainstorming/SKILL.md) develops alternatives and concrete designs. Gei uses those useful design outcomes without its mandatory approval sequence or repository-local design documents.
- [Superpowers systematic debugging](https://github.com/obra/superpowers/blob/main/skills/systematic-debugging/SKILL.md) emphasizes causal investigation and hypothesis checks. Work keeps a short failure-versus-working-path comparison without importing a universal staged workflow.
